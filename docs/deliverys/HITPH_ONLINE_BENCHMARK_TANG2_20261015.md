# Tang2 独占 GPU 0/6/7：无写盘负例推理与组合显存复测

时间：2026-10-15 00:44–00:58 北京时间。主机 Tang2，三张 NVIDIA A40。测试前这三张卡各有一条 `luyq` 的 epoch 1 负例缓存提取任务，已按用户授权停止。Tang3 的 epoch 1 自动重启协调进程在测试期间暂停、测试结束后终止，以免重启这三个分片。其他 GPU 上的提取任务继续运行；未删已有缓存。

停止的分片：Tang2 GPU 0 的 shard 5，GPU 6 的 shard 7（同一 worker 后续还负责 shard 25），GPU 7 的 shard 24。epoch 1 旧写盘流程因此暂时无法完成全部 32 个分片；其余正在运行的分片仍会各自保存已完成结果。Tang3 协调进程原 PID 3388318/3399787 已退出。三张卡在试测结束后保持空闲，没有自动恢复旧提取任务。

脚本：`scripts/benchmark_hitph_online.py`，部署到 Tang2 的 `/data/luyq/hitph_online_benchmark_20261015/repo`。复用现有 Protenix-v1 cycle 4、无 MSA、seed 101、bf16 的 trunk 和 distogram 路径。负例 `s/z/p_dist` 在 GPU 上转 fp16，立即交给 4-block Pairformer＋C pooling 头。头训练使用 bf16 autocast、BCE、AdamW，测试标签为 0，仅用于计时和显存。没有写负例 embedding；远端整个测试目录约 600 KiB，未发现 `.pt` 特征文件。抽样输入来自现有 epoch 1 JSON。同步墙钟计时包含 Python 调度，不等同于纯 CUDA kernel 时间。

| 阶段 | 中位 | 范围 |
|---|---:|---:|
| CPU featurization | 0.434 秒 | 0.423–0.441 秒 |

同样 419 tokens 的首条在 Tang2 独占 GPU 0 上推理 11.947 秒；前次 Tang3 共享 GPU 7 上为 38.246 秒。前次 Tang3 六条测试热身后中位 35.228 秒。硬件同为 A40，但主机、同时运行的任务和样本面板不同；约三倍差距主要指向共卡负载，不能分解为确定的单一原因。旧永久写盘提取累计 86,607 个新样本、`generated_seconds` 2,401,159 秒，即平均约 27.72 秒/条；该指标包括 GPU 推理与保存，口径和负载均不同。

## 分类头显存权衡

GPU 0 额外测试了 4 条 418–419 token 负例的原始分类头，未启用激活重计算。以下数值均包含一份常驻的冻结 Protenix、分类头和一次在线负例；PyTorch 峰值保留未计所有外部 CUDA/context 开销。

| 头训练方式 | 头训练暖样本中位 | PyTorch 峰值分配 | PyTorch 峰值保留 |
|---|---:|---:|---:|
| 原始 4-block 头 | **0.871 秒** | 23,371 MiB | **24,116 MiB** |
| 逐 block 激活重计算，三卡长测最大值 | **1.101 秒** | 9,140 MiB | **10,136 MiB** |

激活重计算把中间激活在反向时重新算一次，头训练段因而约慢 0.23 秒；Protenix 推理段不受这一选择影响。原始头在独占 A40 上可运行，但在 Tang3 之前约 23 GB 空闲的共享卡上显存不足。三卡长测期间 `nvidia-smi` 每卡进程占用约 10.3–10.5 GB。测试结束后 GPU 0/6/7 各空闲约 45,411 MiB。

## 对训练工期的含义

11.8 秒/负例比先前共享卡的 35 秒明显好，但 Protenix 本身仍是主要耗时。只用这三张卡，按当前持续吞吐完成 158,930 次负例在线生成约需 8.2 天。若八张卡都能达到相同单卡速度且完全线性扩展，158,930 次负例推理加 238,395 次头训练的理想计算量约 **3.1 天/epoch**；这是忽略正例 Foldtmp 冷读、CPU 长尾、DDP 通信、验证和显存差异的乐观外推，不能作为工期承诺。省去 Foldtmp 负例写读后不再等待全轮缓存完成，但要进一步缩短 epoch，必须优化 cycle 4 Protenix 计算或改变实验协议。单纯异步预取不能消除约 11.8 秒/负例的计算。
