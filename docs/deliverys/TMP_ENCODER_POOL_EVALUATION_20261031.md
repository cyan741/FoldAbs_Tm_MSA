# 单 GPU 编码器进程池验证

目标：多个冻结 Protenix 编码器生产者供给唯一的分类头和优化器，验证同一个模型训练的吞吐，不再把独立训练副本吞吐作为训练加速。

实现：`scripts/benchmark_encoder_pool.py`。spawn 创建编码器进程，每个拥有独立冻结模型，使用同一 GPU。主进程只有一个分类头和优化器。按固定组索引交错分配编码器任务，分类头按原始组顺序训练，保持每组一次更新。每个生产者最多有一组未确认特征；主进程在 backward、optimizer.step 和 CUDA 同步完成、删除共享特征引用后发 ACK，生产者随后释放。生产者在消费者结束之前保持存活。

传输：torch.multiprocessing.Queue 的 CUDA tensor reducer 使用 CUDA IPC，共享已有显存分配；张量数据不经过 CPU 中转。队列传输句柄和形状等元数据。显式同步编码器完成再发送，避免未完成写入；预热期对每个张量计算 FP64 sum，核对接收值。校验和只是传输检查，不替代完整数值等价测试。接收端不能提前 ACK，否则反向重计算仍可能引用原始特征。bounded queue 与 ACK 限制显存积压。

环境：远程 A100，私有 MPS daemon，正式训练仍保留 step21400 检查点。所有实验写入隔离目录 `/NAS/luyq/foldabs_parallel_eval_20261031/encoder_pool_v1`，不会修改正式权重。

计划测量：1 encoder + 1 head（开启重计算），4 encoder + 1 head（开启重计算），4 encoder + 1 head（关闭重计算）。共同使用前次24组72样本、相同初始分类头/优化器和固定消费顺序。编码器和分类头预热不计时，正式计时包括首次生产、队列等待、训练与尾部排空。记录消费者等待、分类头运行耗时、峰值显存、GPU每秒利用率、每组loss/梯度，以及编码器无梯度。

限制：消费者运行耗时包括共享 GPU 上调度/竞争等待，不能解释为独占 GPU 的 kernel 执行时间。每进程 allocator 峰值之和并非物理显存同时峰值，应参考 nvidia-smi。95%利用率不代表95%算力或带宽利用率，也不能保证提高吞吐。

## 首轮吞吐结果

相同24组72样本、唯一分类头24次更新；不是独立训练副本的吞吐相加。

|编码器进程数|分类头激活重计算|总秒数|条/秒|消费者等待秒|分类头调用秒|物理显存采样峰值|
|---|---|---:|---:|---:|---:|---:|
|1|开启|74.941|0.961|54.403|20.478|10,422 MiB|
|4|开启|59.543|1.209|14.426|45.055|19,137 MiB|
|4|关闭|56.568|1.273|19.992|36.523|49,365 MiB|

4编码器开启重计算比1编码器开启重计算吞吐提高25.9%；4编码器关闭重计算比既有串行关闭重计算71.668秒基线提高26.7%。均为短时首轮结果，不能直接外推完整epoch加速。

4编码器开启/关闭重计算的正式计时窗口中，nvidia-smi每秒采样平均GPU利用率分别99.73%/99.51%，≥95%的采样占98.33%/98.25%。存在低于95%的采样，不是始终≥95%。关闭重计算时主进程仍有35.3%的墙钟时间等待输入；GPU高利用率并不代表分类头无等待。主进程的训练调用在与编码器竞争资源时变慢。

1编码器未记录精确epoch计时边界，遥测截取为近似值，不用于严格利用率对比。4编码器记录了start_epoch/end_epoch，可按精确计时区间过滤遥测。

数值验证仍需独立记录：已有训练模式的1编码器与4编码器输出存在差异，最大logit差0.90625，最大loss差0.09486；不得把传输checksum通过解释为串行训练数值等价。正在通过关闭dropout、保存首组完整特征的隔离运行定位。

## 数值对照结论与部署状态

关闭dropout的8组对照：1编码器与4编码器最大logit差0.64746，最大loss差0.20288。首组完整编码器特征已有差异，故不能仅归因于分类头dropout。再独立重复1编码器配置，仍有最大logit差0.5、最大loss差0.12206，编码器特征同样不完全一致。这证明单编码器基线自身存在跨次运行不可复现问题，但不足以证明多编码器与基线数值等价或差异无害；根因未定位，不能直接归因于BF16舍入或MPS。

CUDA IPC预热张量sum校验通过；所有encoder_has_grad为false，训练loss/gradient_norm有限。功能上实现了多个冻结生产者服务唯一分类头，且实测吞吐提高；正式替换仍需解决/量化特征可复现性、完成长时间吞吐复测、断点恢复与正式DDP集成。当前不将原型部署为正式训练路径。
