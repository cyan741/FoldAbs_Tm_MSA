# 双GPU同步训练基准（隔离实验）

用户要求：显存足够时关闭激活重计算；评估BF16与确定性；开始双卡测试。正式group训练继续保持暂停，未获恢复命令不得启动。

## 实现

`benchmark_encoder_pool_ddp.py`：每张GPU一个分类头消费者，各自有本卡编码器生产者池（CUDA IPC）。两个分类头副本从相同权重与optimizer状态开始，每次处理一个组，backward后通过NCCL对全部分类头梯度求和并除以world_size，再执行optimizer.step。每GPU仅一个NCCL训练rank；编码器不参与梯度同步。

这里采用显式梯度all_reduce，而非DDP自动bucket封装。它实现同一模型的数据并行更新，不能将这次结果描述成独立模型吞吐相加。组等权平均，名义全局batch=6，每步两个组。基准最后对全部分类头参数state_dict做SHA256并跨rank核对，确保两个副本一致；每个编码器无梯度，所有梯度范数检查有限。

`run_encoder_pool_dual_evaluation.py`：私有MPS覆盖GPU0/1，分别启动可见本卡的两个主进程。依次每卡1encoder/48全局组，每卡4encoder/48全局组，每卡4encoder/96全局组。所有case激活重计算关闭、BF16 autocast、FP32稳定atom-to-token聚合、cuEquivariance分类头。全部写隔离目录 `/NAS/luyq/foldabs_parallel_eval_20261031/dual_pool_v1`。结束退出私有MPS，不恢复正式训练。

前两个case使用同一组列表、同一初始模型/optimizer、相同全局batch和更新次数，可以直接比较。最后96组用于较长运行检查。不能拿双卡batch6与此前单卡batch3的不同更新次数，直接宣称同一训练任务线性加速。

## 精度结论与边界

保持BF16 autocast并不必然失去确定性。已定位编码器差异来自BF16 scatter_add_非确定性，实验中只将atom-to-token均值改为FP32确定性分段归约，仍保留其他BF16前向；同输入/权重同进程与跨进程输出已逐位一致。全改FP32并不能自动固定归约顺序或自定义kernel。

cuEquivariance固定特征/权重重复反向测得相对梯度向量L2差约0.03%，定义为norm(g1-g2)/norm(g1)，不是两个梯度范数的相对差。例子norm约0.02409065016765109与0.024090650178413386，范数差仅约1.08e-11，梯度方向cos>0.99999995。该小扰动尚未证明对多轮验证指标无影响；严格逐位复现需Torch分类头+确定性设置（已有8步1vs4对照差0），性能结论不能与快速cuEquivariance混用。

新实验不会隐式改变正式恢复检查点的执行配置。正式未来切换稳定聚合或分类头kernel，需记录为显式执行配置变化。

## 对数值差异的解释

编码器修复前，同一个输入连续推理的probability差异RMS约0.0051，最大约0.46；这不应简单认为可以忽略。替换非确定性BF16 scatter为确定性FP32分段mean后，保留BF16 autocast，已测输入重复差异为0。这些是重复运行差异，不是BF16相对于全FP32参考的精度误差；后者未在本轮测量。

分类头梯度0.03%是向量差的相对L2，不是范数相对差，也不是最终验证指标误差上限。已有8组快速路径1vs4对照，在更新累积后maxlogitdiff0.0625、maxlossdiff0.014392，不能将单次微小梯度差保证为长期完全无影响。速度优先时可保留cuEquivariance并按容差/重复实验评估；严格逐位复现时采用Torch确定性配置。此前开启重计算的8组单生产者对照，分类头累计调用cuEq约5.997秒、Torch确定性配置约12.411秒；该数字包含kernel与确定性设置差异，不能当作关闭重计算下的纯kernel性能比。

## 较长复测与最终状态

每卡4encoder、96全局组288样本、48次共同更新：113.174秒，总吞吐2.54475条/秒。两卡完整head参数SHA256均为ab095e572e001271b3173bc457c6baa3068244caa1d7004144a491a22834b360。所有编码器无梯度、所有更新梯度有限。

计时窗口两卡平均GPU-util为99.22%/99.17%，各99.12%的1秒采样≥95%，短时最低14%/6%；整进程含启动/预热/退出的平均为74.04%/73.07%。每卡显存采样峰值50445MiB（49.26GiB）。不能声称始终≥95%或GPU-util代表峰值算力利用率。

全部基准已退出，私有MPS已关闭，GPU0/1均释放；正式训练保持暂停，恢复点step21600，等待用户明确命令。基准加载之前step21400隔离检查点以保持与已有对照可比，不覆盖正式权重。未将原型接入正式训练/验证/逐epoch保存与恢复流程。

## 用户确认与数值结论澄清

用户确认保留cuEquivariance，采用单卡4编码器+1分类头，双卡共8编码器+2同步分类头副本；显存足够时关闭激活重计算。正式训练继续保持停止，等待明确恢复指令，原型尚需接入正式训练/验证/保存恢复流程。

此前0.0625最大logit差、0.014392最大loss差是两边均使用cuEquivariance的1vs4编码器诊断，不是cuEquivariance对Torch；是8组过程中的最大值，并非最后一次更新后的固定输入对照。该历史诊断开启了激活重计算；详细配置及对应组数值见TMP_ENCODER_POOL_SWEEP_20261031.md。保留cuEquivariance不能承诺整个训练逐位确定。

最新单卡池及双卡池性能实验均已使用MPS，双卡启动器显式启动私有MPS daemon并在结束时退出。当前吞吐已包含MPS条件，不能再将“开启MPS”计为额外未兑现的提速。
